Bash/eval may read anywhere and navigate freely. They may only write inside your cwd/workspace (relative paths) or `/tmp` — never `~/...`, `$HOME`, system dirs, `..` escapes, drives, UNC, or remote schemes. Variable targets (`$OUT`, `%OUT%`, `$(...)`, backticks), `eval`, and decoders (`base64 -d`, `xxd -r`) count as outside — approve first. Triggers when an outside path sits in a write *target* position: after a redirect (`>`/`>>`), an output flag (`of=`, `curl -o`, `wget -O`, `--output`), a write verb with the path as its last argument (`cp`, `mv`, `tee`, `sponge`, `rm`, `rmdir`, `sed -i`, `install`, `dd`, `Out-File`, `Set-Content`, etc.), or inside a write call (`open(..., "w")`, `writeFile(Sync)`, `Bun.write`, `.write_text`). Reads stay allowed: `cat /etc/passwd`, `cp /etc/x .`, `echo $HOME > out.txt`, `cat /etc/passwd | tee /tmp/x` all pass. Vars count as outside even when bound to /tmp: inline the literal /tmp/… path in the redirect or approve first. Same staging rule as file writes: stage under `/tmp`, show exact commands, ask the user to run or approve. Never write outside yourself.
